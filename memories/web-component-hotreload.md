- Web Component `hotReload` pattern in this repo uses `Object.getOwnPropertyNames(NewClass.prototype).forEach(k => ExistingClass.prototype[k] = NewClass.prototype[k])`. This silently breaks getters/setters: it INVOKES the getter on the prototype (often calling DOM methods with non-Element `this` -> "Illegal invocation"), and copies the resulting value rather than the accessor.
- For any component that defines `get`/`set` on the prototype, copy descriptors instead: `var d = Object.getOwnPropertyDescriptor(NewClass.prototype, k); Object.defineProperty(ExistingClass.prototype, k, d);`
- Affected existing files to consider fixing: ~~morphic-window.js~~ (FIXED 2026-06-13: hotReload now uses `Object.getOwnPropertyDescriptor`/`Object.defineProperty` for the prototype copy, because `get borderExtent()` was throwing "Illegal invocation" and breaking every morphic-window hot-reload), workbook-window.js (workbook has `get caption`, `get pages`, `get currentPageIndex`).
- Bootstrapping a fixed hotReload onto a live page whose installed hotReload is broken: fetch the source, strip the `customElements.define(...)` call, `new Function(src+'return Klass')()`, then descriptor-copy prototype+statics onto `customElements.get(tag)`. Note copied methods close over the *temporary* NewClass, so class-static instrumentation on the registered class won't be hit by internal `MorphicWindow._foo` calls — instrument at the DOM/event level instead when debugging.
