- Bug fixed 2026-07-28: **opening a pull-down menu on a remote VW window shrank the PARENT window's mirror.** Reproduced: opening a menu leaves the parent `<morphic-window>` with TWO slotted `<canvas>` children — its real remote surface (e.g. `620×200`, `transferControlToOffscreen`'d, no inline CSS size) PLUS a stray blank default `300×150` canvas (`position:absolute; width:300px; height:150px; display:block`, NOT transferred). `_installCanvasSizeSync`'s `ResizeObserver` observes ALL slotted canvases, so the stray fires `_syncSizeToCanvas` and the wrapper shrank to `310×180` (300+2·5 × 150+25+5), leaving the real canvas overflowing the chrome (title bar narrower than content). Root cause (Caffeine, 2300-ui consumer): `Snowglobe>>mapWindow:`'s recycle path `window world canvasElement: canvas` → `HTML5WorldState>>canvasElement:` → `HTML5FormCanvas onHTML5Canvas:`/`html5Canvas:` → `Webpage>>createWorldOfKind:withCanvas:`, which builds a fresh `<div>` window element, sets `canvas.window`/`div.canvas`, and `body.appendChild(div.appendChild(canvas))` every time a canvas is (re)wrapped — so a menu recycle drags a stray default canvas into the parent's element. Client fix (the reported symptom): new `_windowSurfaceCanvas()` picks the window's REAL surface among slotted canvases — a canvas whose control was transferred to an OffscreenCanvas can no longer yield a 2d context on the main thread (`getContext('2d')` throws or returns null), so filter to transferred canvases (fallback: all) and take the largest by area; `_syncSizeToCanvas` reconciles the wrapper to THAT, never the triggering stray. Heal live windows once with `w._syncSizeToCanvas(w.querySelector('canvas'))` after hotReload. The deeper Caffeine root fix (stop `createWorldOfKind:withCanvas:` re-parenting recycled canvases) is left for later — it's architecturally involved and the stray blank canvas is now harmless (no longer drives size).
- Bug fixed 2026-06-18: the teal focus/hover tint (`:host(:hover) { background-color:#a8c8c8 }`) silently stopped working for any window that had gone through a cutout transition. `_setCutoutMode(false)` used to PIN an inline `this.style.backgroundColor = color` to "restore solid host bg". An inline background-color outranks the `:host(:hover)` shadow rule, so the tint never appeared. The maximize path hid the bug (its `_toggleMaximize` finally did `removeProperty('background-color')`), but the interactive-resize path (`_onResizePointerUp` → `_setCutoutMode(false)`) had no such cleanup, so a resized window kept a permanent inline gray bg. Fix: `_setCutoutMode(false)` now `removeProperty('background-color')` (hands control back to the stylesheet, whose `:host` #c0c0c0 equals the normal lock color) instead of pinning it. hotReload's `_render()` does NOT clear lingering host inline styles, so heal pre-existing affected windows once by `w.style.removeProperty('background-color')`.
- cmd-drag (and opt/ctrl-click) over iframe content works because each content iframe's `contentDocument` gets capture-phase modifier handlers. The window only scans its *light-DOM* iframes (`this.querySelectorAll('iframe')`). Iframes living inside a slotted component's **shadow DOM** (e.g. `<keep-viewer>`'s `.graph-frame` graph iframes) are invisible to that scan, so cmd-drag won't engage over them unless they're registered explicitly. Fix (2026-06-13): the per-iframe attach logic is exposed as static `MorphicWindow._attachModifierClickToIframe(iframe)`; components call it on their shadow iframes. The static iframe-discovery helpers (`_installArmDispatchers`, `_iframeOffsetForDoc`, `_setCmdHeld`, `_startModifierDrag`) now use shadow-aware `MorphicWindow._allIframes()` instead of `document.querySelectorAll('iframe')`.
- Arming defers `_startModifierDrag` via `setTimeout(...,0)`. Synthetic Playwright gestures fired faster than that macrotask can drop the drag (the up() lands before drag listeners attach), so cmd-drag tests are flaky unless you `waitForTimeout(~40ms)` after the threshold-crossing move. Real human drags span real time and are unaffected.
- Current resize cursor strategy for `morphic-window`: window-owned shadow DOM `.resize-hit` bands around the frame, mirrored to host/document cursor with `_setResizeCursor`. Remove stale body-level `[data-morphic-window-resize-surface]` experiments during hot reload; those were misleading for the visible cursor issue.
- DANGER: SqueakJS's own World is rendered inside a top-level `morphic-window` (100vw×100vh, position:fixed). NEVER bulk-remove `morphic-window` elements from the top doc — that detaches SqueakJS and kills the running image. To clear Snowglobe-mapped windows, iterate `Snowglobe windows` in-image and call `closeWindowWithID:` instead.
- Snowglobe (titlebar, non-chromeless) windows shrink-wrap to their slotted `<canvas>`: with no explicit host width/height, `position:absolute` block sizing tracks the canvas (which the resize-frame protocol sets via `canvas.width`/`height`). So height auto-tracks canvas resizes for free; an explicit inline width/height does NOT, and will desync if the canvas later grows (→ canvas overflows the chrome).
- Mirror resize, both directions (2026-07-24): (a) **client→server** — the wrapper's `_onResizePointerUp` sends the new inner extent PLUS `left`/`top` (0/1) edge-drag flags via `onResizeComplete`; `Snowglobe>>resizeWindow:asPer:` forwards them in a `RequestResizeWindow` (20) frame and `SnowglobeMorphicService>>injectInputFrame:` resizes the original, holding the opposite corner fixed when an edge was dragged (**corner-anchoring**). The component already anchors the far corner on the page during the drag (`_onResizePointerMove` moves `left`/`top` for top/left edges); the flags make the SERVER window anchor too. (b) **server→client** — when the original resizes in the Squeak UI the worker resizes the OFFSCREEN canvas from the worker thread, which **bypasses the main-thread `canvas.width` setter** (so the existing `_instrumentCanvasForResizeFade` setter-override never fires, and the pinned wrapper size goes stale — canvas 480 vs wrapper 645). Fix: a `ResizeObserver` on the slotted canvas (`_installCanvasSizeSync` → `_syncSizeToCanvas`, installed from `_attachBehavior` so `hotReload()` re-wires live windows) reconciles the wrapper width/height to the canvas, preserving position, skipping live drags/maximized, and no-op'ing when already in sync (no feedback loop). RO observes the rendered box, which DOES change on an offscreen resize, so it's the reliable trigger.
- Server-side corner-anchoring (2026-07-24): `ResizeWindow` (14) now carries two trailing booleans `leftMoved`/`topMoved`. Producer (`SnowglobeMorphicService`) tracks each window's full **bounds** in `lastExtents` (repurposed from extent; self-migrates via an `isKindOf: Rectangle` guard) and updates it EVERY tick (in `updateExistingWindow:withDamage:`) so per-tick edge deltas are accurate; `emitResizeFor:leftMoved:topMoved:` sends the flags. Consumer's main-thread `onmessage` (in `Snowglobe>>connectTo:` AND `reinstallOnMessage` — reinstall live with `consumer reinstallOnMessage`) reads the 2 booleans for instruction 14 and stashes `mw.__sgAnchor = {leftMoved, topMoved, right, bottom}` (pre-resize viewport edges); `_syncSizeToCanvas` then repositions to hold the anchored corner. GOTCHA that cost a debug cycle: an attribute selector with a value starting with a digit MUST be quoted — `querySelector('morphic-window[data-remote-world-id=1]')` throws (invalid CSS), silently caught; use `[data-remote-world-id="1"]` (or scan `querySelectorAll` + `getAttribute`). A client drag's echo has matching size → `_syncSizeToCanvas` early-returns and clears `__sgAnchor` (no double-anchor).
- Bug fixed 2026-06-16: `_clampToViewport` shrank an oversized host to the viewport by pinning `style.width/height`, but the shrink was ONE-WAY and `_onViewportResize` was a no-op unless web-side maximized. So a window clamped at reload (when the Integrated Browser panel was narrow) kept the stale width after the panel widened, overflowing its canvas. Fix: `_clampToViewport` now releases its prior clamp (tracked via `_clampAppliedW/H` + saved `_preClampW/H`, so it never clobbers a content component's intrinsic inline size) and re-measures before re-applying; `_onViewportResize` re-runs clamp for normal windows too. Pre-existing stale windows (clamped by the old code, no flags) need a one-time heal: for each non-`#embeddedSqueak` window with a direct `<canvas>` child, clear inline width/height and call `_clampToViewport`.
- REGRESSION from the above, fixed 2026-06-16: wiring `_onViewportResize → _clampToViewport` for normal windows meant that on EVERY viewport resize a canvas-backed (Snowglobe-mapped) window could get `style.width/height` pinned by the clamp. That resizes the host chrome WITHOUT going through `onResizeComplete`, so Squeak is never told, the `<canvas>` desyncs from the chrome, and the remote window appears to "keep going away." Fix: `_clampToViewport` now detects `canvasBacked = !!this.querySelector('canvas')` and for those windows clamps POSITION ONLY — it never writes `style.width/height` (sizing belongs to the remote display policy via the resize-frame protocol). The only legitimate path that resizes a Snowglobe window must call `onResizeComplete({x,y,width,height,done})` (see `_onResizePointerUp` and `caffeine-bounds-persist.js`); the clamp is not such a path.
- Frozen snapshot overlays (the `_frozenSnapshotOverlay` / `freezeAll` / `_freezeChromelessSnapshot` / `_thawFrozenSnapshot` machinery, z=4000 body canvases) were REMOVED 2026-07-24 — the Snowglobe display pipeline got cheap enough (fast serialize + bulk binary send + always-on repaints) that the stale-pixel flashes freezing masked no longer appear at current activity levels. - Lifecycle callbacks (`connectedCallback`/`disconnectedCallback`) are captured by the browser at `customElements.define()` time and are NOT patchable by reassigning `MorphicWindow.prototype.*` — a live reassignment is inert (the original captured fn still runs). For live/hot-reload behavior on connect/disconnect, use a re-installable `MutationObserver` on `document.body` `{childList, subtree}` watching added/removed nodes (see `__morphicWindowClampObserver`, which clamps newly-added windows to the viewport). The prototype `connectedCallback`/`disconnectedCallback` edits only take effect on a fresh page load.
